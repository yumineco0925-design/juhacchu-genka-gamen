# 受発注と原価の管理（スプレッドシート版）

設備工事会社の発注、発注検収、請求、労務費を1つのスプレッドシートで持つ例です。月次の締めと予算超過の確認を Apps Script で行います。会社名、工事名、施主、取引先は全て架空です。

## できること

スプレッドシートのメニューに「原価管理」が加わり、次の4つの操作ができます。

| 操作 | 内容 |
|---|---|
| 予算超過の一覧を作る | 工事と費目ごとに予算と発注済を突き合わせ、発注済が予算を超えている組を「予算超過」シートに書き出します。 |
| 月を締める | 最後に締めた月の次の月を締めます。条件を満たさないときは締めず、満たしていない条件と該当の番号を出します。 |
| 締めを解除する | 直近の締め済の月の締めを解除します。理由の入力が必須です。 |
| データの整合を点検する | 4つの点検を行い、結果を「点検結果」シートに書き出します。 |

このほか、発注、発注検収、請求、労務費のシートを編集したときに、締め済の月に入る編集を止めます。

### 予算超過の一覧

発注済は、工事と費目ごとに次の額を足した物です。

- 通常と追加の発注のうち、状態が承認済（「承認済（一部検収）」を含む）か検収済の物の有効発注額
- 打切の発注の、発注検収の累計
- 費目が労務費の組には、労務費シートで計上日が入った行の金額

起票と取消の発注は足しません。減額発注そのものも足しません。費目が労務費の発注も足しません。労務費は労務費シートの行だけで数えます。

有効発注額は、発注金額に、その発注を関連発注番号に持つ承認済の減額発注の額（負の額）を足した額です。発注の区分は、発注金額の符号と関連発注番号で次のように決まります。

| 発注金額 | 関連発注番号 | 区分 |
|---|---|---|
| 負 | どれでも | 減額 |
| 0以上 | あり | 追加 |
| 0以上 | 空 | 通常 |

関連発注番号が空の減額発注は、どの発注の有効発注額にも入りません。

予算は、工事シートの実行予算（当初）の列（費目ごとに4列）の値が元です。これに、予算改定シートで状態が承認済の行の、改定後の額から改定前の額を引いた差を足します。工事シートに無い工事番号の発注は、予算を0円とし、工事名の欄に「（工事シートに無い番号）」と入れます。

書き出す列は 工事番号、工事名、費目、予算、発注済、超過額、原因の発注番号 です。原因の発注番号には、発注日の順に足していって予算を超えた発注と、それより後の発注が入ります。労務費の計上で超えたときは「労務費の計上」と入ります。

一覧は作った時点の集計です。元のシートを直したら、もう一度作ってください。

### 月を締める

次の条件を全て満たすと、確認の画面を出してから締めます。

1. その月の末日が、設定シートの基準日より前である。
2. 前の月が締め済である（締めるのは、最後に締めた月の次の月だけ）。
3. 請求書の日付がその月以前で、状態が受付のままの請求が無い。請求書の日付が空の受付も止めます。差戻しと取消は止めません。
4. その月に施工中だった工事に、その月の労務費の行があり、計上日が入っている。施工中は、着工日の月がその月以前で、施主検収日が空かその月以後の工事です。

次の物は確認の画面に出しますが、締めは止めません。

- 納期がその月の末日以前で、未検収残のある承認済の発注。発注番号を出します。
- 起票のままの発注。発注日が無いので締めの対象外です。件数を出します。

未検収残は、有効発注額から有効な発注検収の累計を引いた額です。

締めると、設定シートの締め済の月に1行加わり、履歴シートに「締め」の行が残ります。変更前の欄には「状態: 未締め」、変更後の欄には「状態: 締め済、回数: 第2回」のように入ります。回数は、その月を締めた回数です。

### 締めを解除する

解除できるのは直近の締め済の月だけです。締めの種類が「繰越」の月は解除できません。

理由を入れる欄が出るので、理由を入れて OK を押します。理由が空のときと、200字を超えるときは解除しません。キャンセルを押すと取りやめます。

解除すると、設定シートの締め済の月からその月が消えます。履歴シートには「締め解除」の行が理由とともに残ります。変更前は「状態: 締め済」、変更後は「状態: 未締め」です。

解除した月をもう一度締めるときは、条件を判定し直します。

### データの整合を点検する

| 点検の種類 | 問題ありとする物 |
|---|---|
| 発注検収の累計と有効発注額 | 発注ごとの有効な発注検収の累計が、有効発注額を超えている。取消の発注に発注検収の累計が残っている。発注シートに無い発注番号の発注検収。減額発注に付いた発注検収。 |
| 確認済の請求と発注検収 | 確認済の請求の発注に、有効な発注検収が無い。発注ごとの確認済の請求額の合計が、発注検収の累計を超えている。発注番号が発注シートに無い確認済の請求。 |
| 起票中の発注と発注日 | 状態が起票の発注に、発注日が入っている。承認済、検収済、打切の発注に、発注日が無い。 |
| 発注の費目 | 費目が材料費、外注費、経費のどれでもない発注。費目が労務費の発注もここに出ます。 |

発注検収は、状態が空か「有効」の行を有効として数えます。点検結果シートは、問題が無い点検も「問題なし」の1行で残します。

### 締め済の月に入る編集を止める

次のシートを編集したときに働きます。

| シート | 行の月を決める列 | 締め済の月の行で直せない列 |
|---|---|---|
| 発注 | 発注日 | 工事番号、関連発注番号、費目、発注金額 |
| 発注検収 | 検収日 | 発注番号、検収額、状態 |
| 請求 | 計上月 | 発注番号、請求額、状態 |
| 労務費 | 月、計上日 | 工事、時間、単価、金額 |

締め済の月は、設定シートの締め済の月の一覧にある月と、一覧の最初の月より前の月です。

1つのセルを編集して、次のどれかに当たると、元の値に戻し、セルに注記を付け、画面の右下に知らせます。

- 行の月を決める列に、締め済の月の日付を入れた。
- 行の月を決める列の、締め済の月の日付を変えたり消したりした。
- 締め済の月の行で、直せない列か、行の月を決めるほかの列を変えた。

締め済の日付を入れたときは「2026-07 は締め済のため入れられません。2026-08 以後の日付にします。」の形で知らせます。

1つのセルでも、元の値が届かないときは空にして知らせます。元の値があったときは、編集の取り消し（Ctrl+Z）で戻してください。

複数のセルをまとめて変えたとき（貼り付けや、範囲を選んでの削除など）は、元の値が取れないため戻しません。締め済の月の行に当たるセルに注記を付けて知らせるので、編集の取り消し（Ctrl+Z）で戻してください。ただし、複数のセルの編集で行の月を締め済の月から外へ動かしたときは、元の月が分からないため知らせません。

行の削除のようにセルの値の編集ではない変更と、設定シートの締め済の月の書き換えでは働きません。

入力の誤りを止めるための物で、書き換えを防ぐ物ではありません。締め済の月の行と設定シートを守るには、シートの保護を併せて使ってください。

## シートの構成

各シートの1行目は見出しです。スクリプトは列を見出しの名前で探すので、列の順を入れ替えても、列を足しても動きます。スクリプトが使う列の見出しが無いときは、どのシートのどの列が無いかを出して止まります。

`setupSheets` を実行すると、下の表の全ての列を持つシートが作られます。

| シート | 列 | スクリプトが使う列 |
|---|---|---|
| 設定 | 項目、値、（空き）、締め済の月、締めの種類 | 全て |
| 工事 | 工事番号、工事名、施主、工事場所、工事種別、状態、営業担当、工事担当、見積金額、受注金額、実行予算（当初）材料費、実行予算（当初）外注費、実行予算（当初）労務費、実行予算（当初）経費、受注日、着工予定日、完工予定日、着工日、施主検収日、施主請求日、請求額、入金日、備考 | 工事番号、工事名、実行予算（当初）の4列、着工日、施主検収日 |
| 予算改定 | 改定番号、工事番号、費目、改定前の額、改定後の額、理由、起案者、起案日、状態、承認者、改定日、取消の理由 | 工事番号、費目、改定前の額、改定後の額、状態 |
| 発注 | 発注番号、工事番号、関連発注番号、取引先、費目、件名、発注金額、納期、状態、予算超過の理由、起票者、起票日、承認者、発注日、取消・打切の理由、備考 | 発注番号、工事番号、関連発注番号、費目、発注金額、納期、状態、発注日 |
| 発注検収 | 検収番号、発注番号、検収日、検収額、内容、状態、訂正元の検収番号、取消の理由、登録者、備考 | 発注番号、検収日、検収額、状態 |
| 請求 | 受付番号、発注番号、取引先、請求書番号、請求書の日付、請求額、受付日、状態、関連する受付番号、確認者、確認日、計上月、差戻し・取消の理由、備考 | 受付番号、発注番号、請求書の日付、請求額、状態、計上月 |
| 労務費 | 工事、月、時間、単価、金額、計上者、計上日 | 計上者のほかの全て |
| 履歴 | 日時、操作者、役割、対象の番号、操作の種類、変更前、変更後、理由、関連する番号 | 全て |

入れる値は次のとおりです。

- 費目: 材料費、外注費、労務費、経費。発注の費目は材料費、外注費、経費のどれかです。
- 発注の状態: 起票、承認済、承認済（一部検収）、検収済、打切、取消
- 予算改定の状態: 起案、承認済、取消。予算に足すのは承認済の行だけです。
- 発注検収の状態: 有効、取消
- 請求の状態: 受付、確認済、差戻し、取消
- 締めの種類: 通常、繰越
- 月の列（締め済の月、請求の計上月、労務費の月）: 2026-08 の形。`setupSheets` で作ったシートでは、この列の書式を書式なしテキストにしてあります。日付として入っていても、その日の月として読みます。
- 金額: 数値。「1,200円」のような文字でも数として読みます。

設定シートの使い方です。

| 列 | 入れる物 |
|---|---|
| 項目と値 | 項目の列に項目名、値の列にその値を入れます。項目は下の表の4つです。 |
| 締め済の月と締めの種類 | 締め済の月の一覧です。最初に、期首の前の月（例 2026-03）を締めの種類「繰越」として1行入れておきます。以後はスクリプトが書き換えます。 |

| 項目 | 値 |
|---|---|
| 基準日 | 日付。締める条件の判定に使います。空のときは今日の日付を使います。 |
| 標準の時間単価 | 1時間あたりの円。労務費の行で金額と単価が空のときに使います。 |
| 操作者 | 締めと解除をする人の姓。履歴の操作者の欄に入ります。 |
| 役割 | 初めは「経理」。履歴の役割の欄に入ります。 |

労務費シートは1工事1か月に1行です。計上日が空の行は未計上として扱います。金額が空の行は、時間を0.5時間単位にそろえて単価を掛け、円未満を切り捨てた額を使います。単価が空なら、設定シートの標準の時間単価を使います。

履歴シートには、締めと締め解除のときにスクリプトが1行足します。操作者と役割には、そのときの設定シートの操作者と役割の値が入ります。値が空なら空のままです。

予算超過と点検結果のシートは、メニューの操作のたびに作り直します。A1のセルの注記に、作った日時が入ります。

## 入れ方

1. 新しいスプレッドシートを作り、メニューの「拡張機能」から「Apps Script」を開きます。
2. 最初からあるファイル（コード.gs）の中身を消し、このフォルダの Code.gs の中身を貼り付けて保存します。
3. 実行する関数に `setupSheets` を選んで実行します。初めて実行するときに承認を求める画面が出るので、自分のアカウントを選んで許可します。確認されていないアプリである旨の画面が出たときは、詳細を開いて先に進みます。
4. 足りないシートが見出しつきで作られ、設定シートに足りない項目が足されます。既にある値は変えません。
5. 設定シートに、基準日、標準の時間単価、操作者の値と、期首の前の月（締めの種類は「繰越」）を入れます。
6. 工事、予算改定、発注、発注検収、請求、労務費のシートに、上の「シートの構成」のとおりにデータを入れます。
7. スプレッドシートを開き直すと、メニューに「原価管理」が出ます。

`onOpen` と `onEdit` は単純トリガーなので、トリガーを設定する必要はありません。スクリプトは V8 ランタイムで動きます。新しく作ったプロジェクトは初めから V8 です。

## 画面版との対応

画面版（業務画面）の決まりのうち、このスプレッドシート版にあるのは次の物です。

- 発注済と有効発注額の数え方（減額発注、打切、労務費の扱い）と、発注の区分の決め方
- 予算の数え方（当初の額に、承認済の予算改定の差を足す）
- 締める条件と、止めずに知らせる物
- 締め済の月の日付を入れさせないことと、締め済の月の記録を直させないこと
- 締めの解除は直近の月だけで理由が必須、繰越の月は解除できないこと、締めた回数を履歴に残すこと
- 労務費の金額の計算（0.5時間単位にそろえ、円未満を切り捨てる）

次の物はありません。

- 役割ごとの権限。誰でも全ての列を編集でき、締めと解除もメニューから行えます。履歴の操作者と役割は設定シートの値で、実際に操作した人とは突き合わせません。
- 状態の移り方とその条件の確認。状態は手で書き換えます。食い違いの一部は点検で拾います。
- 発注の承認のときの予算超過の判定と、予算超過の理由の必須入力
- 予算改定の起案と承認。予算改定シートは、承認済の行を読むだけです。
- 発生原価、計上額、粗利（発生原価ベース）の集計。一覧で比べるのは予算と発注済だけです。
- 発注検収の訂正（マイナス額）、請求の差戻しと再受付のつながり、二重の請求の疑いの判定
- 締めと締め解除のほかの操作の履歴
- 取引先の管理と帳票の出力

公開されている情報と一般的な商慣行をもとにした自主制作です。

実在する企業の業務、データ、資料は使っていません。

確認が要る事柄は、決めつけずに分けてあります。
